**Quora Question Pairs** — виявлення дублікатів питань

Класифікаційна модель, що визначає, чи є два питання з Quora семантичними дублікатами один одного.

***Бізнес-задача та мета***

На платформах типу Quora користувачі часто ставлять одне й те саме питання різними словами. Це призводить до:

- дублювання контенту та розпорошення відповідей між кількома однаковими темами;
- гіршого досвіду користувача (доводиться шукати відповідь у кількох місцях замість однієї консолідованої теми);
- зайвого навантаження на модераторів, які вручну обʼєднують дублікати.

***Мета проєкту*** — побудувати модель, яка на вхід приймає пару питань (текст 1, текст 2) і передбачає ймовірність того, що вони є дублікатами. Це дозволяє автоматично:

- підказувати користувачу схожі вже задані питання ще до публікації нового;
- автоматично обʼєднувати дублікати або позначати їх для модератора;
- покращувати якість пошуку по базі питань.

***Дані***

Файли: quora_question_pairs_train.csv.zip, quora_question_pairs_test.csv.zip
Розмір: ~323 432 пари питань у вихідному train-файлі (після видалення 3 рядків з пропущеними значеннями); додатково розділено на train/validation (80/20, стратифіковано за міткою)
Train: 258 743 рядки
Validation: 64 686 рядків
Поля: qid1, qid2, question1, question2, is_duplicate (0/1)
Баланс класів: 63.0% не дублікати (0), 36.9% дублікати (1) — помірний дисбаланс, врахований через stratify при спліті

***Підхід до оцінювання***

Основна метрика: Log Loss (Cross-Entropy Loss).
Обрана як основна, оскільки враховує впевненість моделі у передбаченні (ймовірність), а не лише фінальний клас — це важливо для задачі, де можна далі калібрувати поріг прийняття рішення залежно від бізнес-контексту (наприклад, при автоматичному обʼєднанні дублікатів варто вимагати вищу впевненість, ніж при простій підказці користувачу).

***Допоміжні метрики***:

- F1-score (окремо для кожного класу) — для оцінки балансу precision/recall в умовах дисбалансу класів
- Confusion Matrix — для якісного аналізу типів помилок
- Accuracy — як загальнозрозумілий орієнтир

***Підхід до розв'язку***

Feature Engineering

- Очищення тексту: токенізація (NLTK word_tokenize), приведення до нижнього регістру, видалення стоп-слів, стемінг (SnowballStemmer)
- TF-IDF векторизація: 15 000 ознак, уніграми + біграми (ngram_range=(1,2)), навчена лише на train (без витоку даних)

Додаткові інженерні ознаки:
- Jaccard similarity (word_share_ratio) — частка спільних слів між двома питаннями
- Manhattan та Euclidean відстані між TF-IDF векторами питань
- BERT cosine similarity (bert-base-uncased, mean pooling) — на підвибірці через обчислювальні обмеження

***Моделі***
- Baseline: Logistic Regression на конкатенованих TF-IDF векторах обох питань + додаткові ознаки
- Logistic Regression (tuned): підбір C через GridSearchCV (scoring='neg_log_loss', cv=3)
- LightGBM Classifier: градієнтний бустинг над деревами
- Random Forest Classifier: з підбором гіперпараметрів через RandomizedSearchCV
- Logistic Regression + BERT similarity: baseline-модель, доповнена BERT cosine similarity як ознакою (на підвибірці 5000 train / 1000 val / 1000 test)

## Висновки

**Яка модель працює найкраще і чому.** 
Найкращий результат на test — Логістична регресія з параметром C=1.0 (Log Loss на тесті 0.4332). Вона працювала з текстом, розбитим на окремі слова та пари слів (TF-IDF), а також використовувала три сконструйовані ознаки — частку спільних слів (word_share_ratio), Manhattan та Euclidean відстані. Точність (Accuracy) моделі склала 79%.

**Практичні інсайти.** 
- Проста фіча (Jaccard similarity) виявилось дуже потужною ознакою — звичайна частка спільних слів між двома питаннями виявилася найціннішою підказкою для моделей. У дублікатів цей показник у середньому складає 0.58, а у різних питань — лише 0.37.
- Виключення питальних слів (why/what/which/how) зі стоп-слів покращило якість моделі, оскільки саме ці слова визначають тип і намір питання — раніше вони видалялись на етапі препроцесингу нарівні зі справді неінформативними стоп-словами, що призводило до частини помилкових спрацювань.
- BERT має потенціал, але вимагає ресурсів. Нейромережа BERT показала гірший результат тільки тому, що ми змогли прогнати через неї дуже мало даних через обмеження.

**Практичне застосування в бізнесі.** Модель придатна для підказки користувачу схожих питань під час набору нового, напівавтоматичної модерації дублікатів та покращення пошуку по базі знань.

**Обмеження моделі.** TF-IDF не розпізнає перефразування й синоніми так, як контекстні ембединги. BERT-експеримент проведено лише на підвибірці через обчислювальні обмеження.

**Що можна покращити далі.** Порахувати BERT-ембединги пакетно на повному датасеті; спробувати fine-tuning BERT; розширити пошук гіперпараметрів для LightGBM (наразі не проводився) і Random Forest на повному датасеті.
